# Data pipeline

The pipeline has four steps:

```
scenario JSON ──(simulator + tracker)──▶ raw export ──(import)──▶ processed run ──(model)──▶ scores
   data/scenarios, simulation_plans      raw-data package        data/processed         results/
```

| Step | Input | Code | Output | In the release? |
|---|---|---|---|---|
| 1. Scenario generation | a region's scenario, a run plan row | `deepdas.batches.<set>` (`build`) | `<run>.sim.json`, injection record | plans and generators: yes |
| 2. Simulation | the scenario | `deepdas.sim.runner.run_scenario` (SimStudio simulator and tracker, `deepdas.fp`, unchanged) | export (track rows 50 Hz + tracking audit), `truth_trail.parquet`, `run.json`, `realization.json` | **raw-data package**; `realization.json` of the final test: yes |
| 3. Import | the export | `deepdas.importing.import_run` (`data/import_exports.py` → `data/channels.py` → `data/quality.py`; amplitude by `amplitude.amp_on_bins`) | `<run>_channels.parquet`, `<run>_amp.parquet`, `<run>_track_meta.parquet` | yes, for every set |
| 4. Labelling | the truth of the run | the `realization` rule of the set (`docs/ANOMALY_TYPES.md`) | the `vehicles.csv` of the set | yes |

**Separation of truth and input.**
- **Step 3 reads only the exported tracker output and the map.** The truth columns of the export (`TRACK_TRUTH_DROPPED` in `data/import_exports.py`) are dropped on read.
- **The oracle vehicle id** is kept as metadata, only to group tracks per simulated vehicle for labelling and for the vehicle-unit tables.
- **Step 4 reads only the truth,** and never enters the model.

The audit is in `LEAKAGE_AUDIT.md`.

## Simulation
- **Simulator.** The SimStudio Final Project simulator (`src/deepdas/fp/`) is included unchanged.
  - 0.02 s time step, recordings capped at 120 s.
  - IDM car following with stochastic speed profiles; DAS, camera and GPS sensor models; Kalman tracking with the project's association.
- **Background traffic.** It is generated by the project's own corpus generator (`deepdas.batches.populate_vehicles`, verbatim) with a seed per run.
- **Injections.** Every injection uses only public simulator controls:
  - per-vehicle parameters (speed profile, weight, lateral mode, IDM headway);
  - a planned route (`set_vehicle_route`);
  - the anomaly director (`deepdas.sim.anomaly_director`), which issues brake, stall, freeze and release actions at planned times or positions.
- **Determinism.** A run is fully determined by its scenario JSON and simulation seed. Regenerating a run with the shipped generator and plan gives an identical scenario, truth trail and realisation record. This is verified in check E6.

## Import (step 3)
1. **Read the export.** The 50 Hz track rows (`x_hat`, `y_hat`, velocity and acceleration estimates, update kind) and sensor presence (`has_das`, `has_cam`, `has_gps`) are read from the Excel tracking audit with python-calamine.
2. **Bin.** Rows are averaged into 0.1 s bins per track; time is relative to the track start.
3. **Map-match** to the lane polylines of the scenario. The match is direction-aware and has hysteresis; a bin more than 8 m from every lane counts as off-road. The road-frame channels and the leader channels are then computed (`docs/ARCHITECTURE.md` §1).
4. **Amplitude.** Each DAS detection of the tracking audit is assigned to the bin of the DAS row with the same 0.02 s tick, or else the nearest within 0.015 s. The bin value is the mean log10 amplitude.
5. **Quality.** The burn-in (the first 1 s) is flagged, and the label-free quality gate is applied. `usable` = ≥ 32 valid bins and the gate passes.

## Processed sets (`data/processed/`)

| Set | Content | Role |
|---|---|---|
| `normal_corpus/` | 14,784 tracks, mostly the 12 normal scenario types of the 148 North-TLV regions; also the background, injected and severity tracks of the unsupervised study | training (train), selection (val_A), thresholds (val_B), development false alarms (test split) |
| `development_cases/` | 9 development cases (`cases.csv`): 5 SimStudio anomaly scenarios + 4 controlled scenarios that realise the anomaly | development |
| `anomaly_sets/cross_region/` | 54 runs, 9 types × 6, in 6 regions | training / validation |
| `anomaly_sets/tailgating_routes/` | 36 runs, tailgating on planned routes | training / validation |
| `anomaly_sets/tailgating_matched_controls/` | 24 tailgating + 24 matched control runs | training |
| `anomaly_sets/stalls_and_stops/` | stall slots (3 stop modes) with controls and legitimate stops; contains stallval | training / validation |
| `anomaly_sets/legitimate_stop_validation/` | stopval2: 24 slots × 5 runs | validation |
| `anomaly_sets/new_scene_check/` | 9 injections in a new scene of each test region | secondary diagnostic (not independent) |
| `final_test/` | 228 runs of the independent final test | **final test only** |
| `research/07_targeted_data_study/data/` | 314 runs of study 07 | research (validation only) |

**Contents of each set:**
- `runs/` (three parquet files per run);
- `vehicles.csv`: one row per simulated vehicle, with its label and the keys of its tracks;
- for the generated sets, the run plan under `data/simulation_plans/<set>/`.

## Labels in `vehicles.csv`

| Label | Meaning | Used as |
|---|---|---|
| `anomaly_verified` | injected vehicle whose anomaly is confirmed in truth | positive |
| `normal_unaffected_background`, `normal_scene` | background vehicle with no stop ≥ 2 s and a minimum gap ≥ 5 m | normal |
| `normal_matched_control`, `normal_targeted_control` | control run vehicle meeting its clean rule | normal |
| `normal_legit_stop` | verified legitimate stop (1–10 s, decel < 4 m/s²) | normal |
| `*_UNVERIFIED_excluded`, `background_*excluded`, `leader_or_target_excluded`, `control_NOT_clean_excluded` | did not meet its definition | **excluded and counted**, never relabelled |

## Region splits (`data/processed/normal_corpus/splits.json`)
- The 148 regions are split by region, with seed 0 and a one-tile buffer: 98 train, 21 val_A, 21 val_B and 8 test.
- **Every simulated set follows this split:**
  - training anomalies come only from train regions;
  - validation anomalies only from val_A regions;
  - the final test only from the 8 test regions.
- Thresholds use only val_B normals.
